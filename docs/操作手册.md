## 1. 先理解三件事

这三条决定了你看到的每个数字是什么意思。

**① 方案是规则，目录是结果。**
「杜威十进」「中图法」「自定义方案」都只是**一套类目 + 编码规则**。它们本身不建任何文件夹；文件夹是整理时按你的收藏建出来的。所以设置页的主按钮是「选用这套方案」，而不是「安装」。

**② 书签树是单父树。**
一个书签只能待在一个目录里。想表达「既属于 A 又属于 B」，用**标签**（详情抽屉里加），不要试图靠目录。

**③ 目录是分类法的投影。**
目录标题写成「`100 编程与后端`」这种「编码 + 空格 + 名字」的格式，扩展才认得它是一条类目；改了名字等于换了身份。`待归类` 是收件箱，不算类目。

## 2. 安装与第一次配置

### 2.1 装扩展

1. 打开 `chrome://extensions`，右上角开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选择 `guizang-extension` 目录。
3. 工具栏出现归藏图标即成功。

### 2.2 选一套分类方案（必做）

1. 任一页面点扩展图标 → 弹窗右上角齿轮，或右键扩展图标 →「选项」。
2. 找到「分类体系映射与自定义方案」，看每张方案卡的说明：
   - 杜威十进：`000–900` 共 10 类，最常见；
   - 中图法（12 / 22 类）：字母编码；
   - PARA / 精简五类：类目少、适合先跑通。
3. 点开一张卡，点 **「选用这套方案」**。
   期望：提示「已选用（没有建任何目录）」，书签栏没有任何变化。

> 想让扩展先看看你的收藏再决定建哪些目录，就走第 5 章的「整理」。

### 2.3 配模型（可选，但推荐）

不配也能用：归类退回本地关键词规则（最高 0.68，界面明确标「本地规则」；一个关键词都没命中就直接拒判，不强塞 `000`）。**但「派生二级」和「因书立目」必须有模型。**

1. 设置页「模型配置」：填 Base URL、API Key、模型标识。
   - DeepSeek：`https://api.deepseek.com/v1` + `deepseek-chat`
   - OpenAI：`https://api.openai.com/v1` + `gpt-4o-mini`
   - Ollama：`http://localhost:11434/v1` + 本地模型名
2. 点「测试连接」，期望显示「通了：…」。
3. 点「保存模型与检测参数」。

参数默认值：每批 24 条、单批超时 120 秒、`max_tokens` 3000、并发探测 4、单批检测上限 60。推理模型（会先思考再回答的）请把 `max_tokens` 提到 8000 以上。

### 2.4 认识书库界面

点扩展图标 →「打开书库」，或快捷键 `Alt+Shift+G`。

- **左栏**：全部收藏 / 星标 / 稍后阅读 / 待归类 / 归类建议 / 整理与洗白 / 失效类 / 重复 / 未检测 / 常阅与吃灰 / 分类 / 标签。
- **中间**：书签列表，三种视图（列表、卡片墙、紧凑），`V` 键循环。
- **右侧**：详情抽屉或归类建议，`I` 键打开详情。
- 顶栏：搜索（`/` 或 `⌘K`）、AI 归类、检测失效、命令面板（`⌘⇧P`）、配色、设置。

## 3. 收录：把网页存进来

四种方式，都会落到「待归类」（除非你当场选了分类）：

| 方式 | 操作 | 结果 |
|---|---|---|
| 弹窗收藏 | 点图标 → 选分类（或不选）→ 保存 | 存进所选目录或待归类 |
| 快捷键收藏 | `Alt+Shift+S` | 当前页收进待归类 |
| 收整窗 | 弹窗里「收本窗标签页」或 `Alt+Shift+W` | 当前窗口全部标签页收进待归类，自动去重 |
| 右键菜单 | 页面右键 → 归藏 | 同弹窗 |

弹窗里还能顺手加星标、写批注（批注和标签都存在本地）。

## 4. 归类：让 AI 给建议，你点头才动

### 4.1 生成建议

1. 左栏点「待归类」，点列表上方 **「AI 归类这 N 条」**。
2. 先跑本地规则，只有本地没把握的才送模型；进度按条走，随时可「停止」，已拿到的建议会保留。

### 4.2 看建议

每条建议卡上有四样东西：**当前分类 → 目标分类**、**置信度**、**一句理由**、**血缘**（`模型名 · p2`，p2 是当前提示词版本；本地规则与历史改判偏好没有这一行，也不假装有）。

置信度有两个门槛，别混：

- **建议卡上的「拿不准」标签**：置信度 < 0.75 就标；
- **执行闸门**：置信度 < 0.65 记为「拿不准」，默认不进执行清单；0.65 及以上算「可移」。

所以 0.65–0.75 之间的建议会带着「拿不准」标签，但仍会被执行。

### 4.3 处理建议

- **接受**：真的把书签移过去（可撤销）。
- **改判**：自己挑一个类目；同上，会把「这个域名→这个类目」记进改判记忆，下次优先命中。
- **忽略**：丢掉这条建议。
- **接受有把握的 N 条**：只搬置信度 ≥ 0.65 的；
- **连「拿不准」一起接受**：会把低于阈值的也搬，点之前会再确认一次。

所有「接受」都走统一提交：先自动整树备份、按 25 条一批写预写日志，事后可在整理日志里撤销。

### 4.4 建议会在什么时候消失

- 书签被删了；
- 目标目录被改名/删掉了（会自动剔除，提示「有 N 条建议的目标类目已不存在」）；
- 你换了分类方案：**能按类名对上的建议会迁移到新编码，对不上的作废**；域名改判记忆同步迁移；还没执行的旧计划会被显式作废。提示里分别报出迁移与作废的条数。

## 5. 整理：把书签归位

入口：左栏「整理与洗白」。这一步只做两件事——**建缺的目录**、**把书签 move 到判出来的类目**。不删目录、不删书签；判到「和现在一样」的条目根本不会进计划。

### 5.1 选范围

| 范围 | 会看哪些书签 | 适合 |
|---|---|---|
| 仅待归类 | 只看没有分类的 | 日常收新书签；目标目录缺了会按需创建 |
| 全库巡检错放 | 全部书签，优先「还不在方案类目里」的 | 定期体检、纠正错放；保留现存二级 |
| 按方案建档 | 全部书签，判定用方案定义的类目 | 第一次把方案落地 |

### 5.2 选「目录结构」（按方案建档时）

| 选项 | 目录怎么来 | 旧目录 |
|---|---|---|
| **按收藏生长**（推荐） | 只建真正命中书签的类目，零空文件夹；可开「按收藏派生二级」 | 保留，空的也不动 |
| **照方案建全** | 方案定义几个类目就建几个（`000–900`，自定义方案的二级也算），包含空目录占位 | 保留 |
| **全新重建** | 先整树备份，再把**全部**书签按方案重判（旧分类不作数）；执行后清掉搬空的旧类目目录 | 搬空的会被清理（撤销可重建） |

### 5.3 生成计划

点 **「生成整理计划」**。生成过程有三个阶段：预筛 → 模型判断（按批）→ 按收藏派生二级（若勾选）。随时可停。

「按收藏派生二级」默认关闭，只在「按收藏生长 / 全新重建」下可选，且只对**尚无二级、命中 ≥6 条**的一级类目做聚类。

计划里怎么看：

- **新建目录 N**：这次会建几个；
- **可移 N**：真正会动的条数；
- **拿不准 / 跳过 / 动不了**：不会动的三类（动不了＝受管书签，企业策略下发的那种）；
- 每行有「当前 → 目标」，带「（新建目录）」标记的说明目标还不存在；
- 有二级时按「一级 → 二级」分组显示；
- 「全新重建」还会显示「已备份整树（时间）」与「预计清理 N 个（编码…）」。

### 5.4 执行与撤销

1. 点 **「执行 N 条」**（默认只执行「可移」；勾「连『拿不准』一起执行」会多执行一批）。
2. 动手前会自动做一份整树备份；执行时每 25 条一批，先把挪动意图写进预写日志再动手。
3. 执行完，「最近整理与归类日志（可撤销）」里会多一条：**移动 N 条，清理 M 个空目录**。
4. 点 **「撤销」**（会二次确认）：书签搬回原位、被删的旧目录重建、本次新建的空目录清掉——回到执行前的样子。

## 6. 二级目录：拆开太大的类目

### 6.1 三种产生二级的方式

| 方式 | 入口 | 说明 |
|---|---|---|
| 生成计划时自动派生 | 整理面板「按收藏派生二级目录」 | 每个 ≥6 条的一级交模型分 2–5 个子类，一并进计划 |
| 计划里再拆 | 计划页脚「再拆一层二级」 | 对已有计划里每个 ≥6 条的一级，分组问模型 |
| 直接拆某个目录 | 打开类目 → 头部「拆分此目录」 | 只处理这个目录的条目；≥6 条且需模型。**它只生成一份拆分计划**并切到整理视图，审阅、剔除后再执行 |

### 6.2 编码规则

子类编码 = **父编码首位 + 10n**：`100` → `110 / 120 / …`，`000` → `010 / 020 / …`；每个父类最多 9 个。字母编码（中图法 `T` 之类）不支持二级，会直接告诉你原因。

### 6.3 拆分只出计划，执行由你点

点「拆分此目录」只会生成一份拆分计划（提示「已生成 N 个二级目录的拆分计划…」），
切到整理视图后你可以剔除、改判，再点「执行」；备份、预写日志与撤销照旧。

### 6.4 拆完之后怎么显示

- 分类栏里二级缩进挂在父类下面，父类行标「含 N 个子类」；
- 点开一级目录：标题数字是**整枝合计**（子类之和），列表按子类分组列出全部后代书签；
- 一级目录里没有直接书签时，提示「这一级没有直接书签」，不会显示成空目录。

## 7. 从收藏里长分类法（因书立目）

当方案给不了你想要的分类时，让模型看你的收藏自己归纳。

1. 设置页「从收藏里归纳分类法」→ **「开始归纳」**。
   期望：进度跑完出草稿。需要模型；书签少于 30 条会被拒绝。
2. **审定**：改类名、删掉不需要的类目（删掉的成员会回到「未覆盖」，不会丢）。
3. 点 **「落成目录并启用」**：把审定后的类目建成真实文件夹，并设为当前方案。

草稿阶段有「增量扩展」：只处理还没归入的条目，按站点聚成新类目建议，接受后要再审定、再落成。

### 按收藏裁剪为草稿（另一条路）

设置页方案卡里的 **「按收藏裁剪为草稿」**：保留方案的编码体系，用本地规则把你的收藏铺进去，**只留下真有收藏的类目**（0 条的剪掉），做成草稿等你审定。它不调模型，所以覆盖不全；要更准就裁完再走一次「整理 → 按方案建档」。

## 8. 体检：失效、重复、跳转、吃灰

| 项目 | 入口 | 说明 |
|---|---|---|
| 失效检测 | 顶栏「检测失效」 | 真实轻量请求核验状态码。五档：ok / 疑似（403、429）/ 失效 / 超时·拒连 / 已跳转。单批默认 60 条、并发 4 |
| 重复书签 | 左栏「重复书签」 | 按规范化地址（忽略追踪参数、锚点、www）分组，每组保留一条，可一键清理（会二次确认，可撤销） |
| 已跳转 | 左栏「已跳转」 | 301/302 的集中处理，可一键更新为新地址（会二次确认，可撤销） |
| 常阅与吃灰 | 左栏「常阅与吃灰」 | 需要按需授予 `history` 权限；读本地历史，不外传 |
| 导出 | 命令面板 → 导出 Obsidian Markdown / HTML | 标准格式，可导入任意浏览器 |

## 9. 安全网：备份、撤销、恢复

### 9.1 三种记录，别混

| 名字 | 是什么 | 用在哪 |
|---|---|---|
| 预写日志（WAL） | 动手**之前**记下「从哪到哪」 | 执行中途崩了，下次打开整理会提示「上次提交中断了」，可「按记录回滚」或「清掉记录」 |
| 撤销日志（journal） | 动手**之后**记一笔 | 整理日志里的「撤销」 |
| 整树备份 | 完整书签树快照 | 灾难恢复；环形保留最近 3 份 |

### 9.2 备份

- 自动：每次整理执行前、每次恢复前，都会自动备份。
- 手动：设置页「立即备份」。
- 导出：设置页「导出最新」，得到 JSON，可长期留档。

### 9.3 恢复（两种，别点错）

| 方式 | 做什么 | 什么时候用 |
|---|---|---|
| **安全恢复** | 把快照写成书签栏下的「归藏恢复 时间」副本，现有书签一条不动；这个容器不参与类目识别 | 想对比、想挑着搬回来 |
| **替换恢复** | 先自动备份当前树，再清空书签栏与「其他书签」的内容，把快照原样写回；按新旧 ID 映射自动保留标签、批注与星标；受管书签删不掉会跳过并计数 | 真要把书签树退回某个时间点 |

导入 JSON 时同样会让你二选一。

### 9.4 二次确认

下面这些都会先弹确认框（危险按钮是红色，`Esc` 或点遮罩取消）：

撤销整理、按记录回滚、清理重复、批量删除书签、批量改名、更新跳转、「连拿不准一起接受」、清空检测记录、重置归类建议、删除全部备份、安全恢复、替换恢复。

## 11. 故障排查

| 现象 | 多半是因为 | 怎么办 |
|---|---|---|
| 「还没选用方案…」 | 设置页没点「选用这套方案」 | 去设置页点一张方案卡 |
| 「这个目录只有 N 条，少于 6 条不必拆」 | 拆分门槛 | 攒够 6 条再拆，或换个大类目 |
| 「字母编码的类目还不支持拆二级」 | 二级编码是「父首位 + 10n」，`T10` 认不出 | 用数字方案，或手工建子目录 |
| 「模型给出的子类少于 2 个」 | 模型输出不合格 | 换个模型或稍后再试 |
| 「目标目录冲突：100（…），未执行移动」 | 计划生成后目录被改名 | 重新生成计划再执行 |
| 执行后 toast 说「K 条没搬成」 | 受管书签或目标目录被删 | 看计划里的「动不了」，受管书签移不了是浏览器策略 |
| 「上次提交中断了：意图里记录了 N 条」 | 执行中后台被回收 | 点「按记录回滚」，或「就这样，清掉记录」 |
| 生成计划一直不动 | 单批上限 120 秒，失败会重试一次 | 等；或调小每批条数、调大超时 |
| 归类建议变少了 | 目标目录没了 / 换了方案 | 看提示里的「迁移 N 条，作废 M 条」 |
| 恢复后书签重复出现 | 用了「安全恢复」，副本和现有目录重号 | 用「替换恢复」；副本容器已不参与统计 |

## 12. 已知边界

- **二级只有一层**：更深的层级既不支持写，也不会被识别。
- **字母方案不支持二级**（中图法 `T` 等）。
- **派生二级需要模型**；没配 Key 时开关不可用，只生成一级，不会假装分过。
- **受管书签动不了**：企业策略下发的书签，Chrome 拒绝移动/删除，计划里会标出来。
- **备份是环形的**：第 4 份会挤掉最旧的一份；要长期留档请「导出最新」。
- **管理页一次最多画 400 行**：几千条收藏时用搜索或选分类缩小范围。
- **整理每轮默认 200 条**，可改 500 / 1000 / 全部；「全新生成」不受这个限制（按定义就是全部重判）。
- **检测有上限**：单批默认 60 条，并发 4；开太大容易被源站限流。
- **新目录没对应书签就会是空的**：选「照方案建全」时如此，这是选项的语义，不是 bug。
- **本地规则最高 0.68，零命中直接拒判**：不配模型时，没有关键词可依据的书签会留在「跳过」，不会硬塞一个“综合类”。

## 13. 数据与隐私

- 所有数据都在本地 `chrome.storage.local`：分类、标签、批注、改判记忆、API Key、备份快照。除模型请求外不发往任何服务器。
- 失效检测会向你收藏的站点发轻量 HTTP 请求（HEAD/GET 前 20KB），用于判断状态码。
- 浏览历史只在「常阅与吃灰」里按需授权读取，且只在本机比对。
- 恢复与替换前都会自动备份；「替换恢复」是不可逆动作，但有备份可回退。
